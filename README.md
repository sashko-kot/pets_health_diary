# Дневник здоровья грызунов

## Назначение и предметная область

Приложение помогает вести дневник ухода за домашними грызунами: хранить
сведения о питомцах и хозяевах, отслеживать вес, активность, аппетит и
симптомы. В проекте есть хозяева, питомцы и записи осмотров. Питомец связан
с хозяином через `owner_id`, запись осмотра — с питомцем через `pet_id`.

В проекте сохранена консольная версия (`main.py`) и добавлен веб-интерфейс на
Django 5.2. Данные предметной области хранятся в JSON:

- `data/owners.json` — хозяева;
- `data/pets.json` — грызуны и их хозяева;
- `data/records.json` — записи дневника здоровья.

## Структура проекта

```text
config/             настройки и URL-маршруты Django-проекта
  settings.py       настройки проекта и список приложений
  urls.py           корневые URL-маршруты
  asgi.py, wsgi.py  точки запуска приложения
homepage/           главная страница и общий каркас HTML
pets/               список питомцев и страницы их карточек
records/            список записей здоровья и страницы записей
models/             предметные сущности и операции с ними
  owners.py         хозяева и поиск хозяина
  pets.py           грызуны, поиск, сортировка и оценка веса
  records.py        записи осмотров и операции с ними
data/               JSON-данные хозяев, питомцев и записей
storage.py          загрузка и сохранение JSON
main.py             консольная версия приложения
manage.py           команды управления Django-проектом
requirements.txt    зависимости веб-приложения
requirements-dev.txt инструменты разработки и тестирования
pytest.ini          настройки обнаружения Django-тестов в pytest
```

Приложения Django зарегистрированы в `INSTALLED_APPS` файла
`config/settings.py`. Функции работы с предметными сущностями расположены в
`models/`, а загрузчик `storage.py` используется как консольной версией, так
и Django-представлениями.

## Страницы и URL

| Страница | URL | Содержание |
| --- | --- | --- |
| Главная | `/` | Описание проекта и ссылки на разделы |
| Питомцы | `/pets/` | Список грызунов, их видов, хозяев и веса |
| Карточка питомца | `/pets/<int:pet_id>/` | Данные питомца, оценка веса и история здоровья |
| Дневник здоровья | `/records/` | Записи осмотров с питомцами и хозяевами |
| Запись дневника | `/records/<int:record_id>/` | Осмотр, связанные питомец и хозяин |
| Администрирование Django | `/admin/` | Стандартная панель Django |

Если питомец или запись с указанным ID отсутствует, страница детали возвращает
HTTP 404. Для URL, которому не соответствует маршрут, используется общий
обработчик `page_not_found()`.

## Основные view-функции

- `homepage.views.page(title, content)` формирует единый HTML-каркас:
  заголовок документа, навигацию, адаптивный viewport и подключение Bootstrap.
- `homepage.views.index(request)` отображает главную страницу.
- `homepage.views.page_not_found(request, exception)` формирует страницу 404.
- `pets.views.pets_list(request)` загружает и отображает список питомцев.
- `pets.views.pet_detail(request, pet_id)` ищет грызуна и показывает его
  карточку и историю записей.
- `records.views.records_list(request)` отображает записи о здоровье.
- `records.views.record_detail(request, record_id)` показывает отдельный
  осмотр и связанные сведения о питомце и хозяине.

Маршруты приложений подключены в `config/urls.py` через `include()`, а сами
маршруты определены в `homepage/urls.py`, `pets/urls.py` и `records/urls.py`.

## HTML, CSS и Bootstrap

HTML-страницы формируются в view-функциях и собираются общим каркасом
`page()`. Для оформления используется Bootstrap 5.3, подключённый через CDN.
В разметке применяются классы навигации, контейнеров, карточек, кнопок и
списков Bootstrap. Метатег `viewport` обеспечивает адаптивное отображение на
узких экранах. Отдельные CSS-файлы пока не используются.

## Установка и запуск

Из корневого каталога проекта в PowerShell:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py runserver
```

Откройте `http://127.0.0.1:8000/`. Для запуска консольной версии используйте:

```powershell
.\venv\Scripts\python.exe main.py
```

## Текущее состояние

Реализованы Django-проект и три приложения: `homepage`, `pets` и `records`.
Веб-страницы читают JSON-данные, показывают списки и страницы деталей,
поддерживают переходы между связанными объектами и корректно обрабатывают
отсутствующие записи. Консольная версия сохранена и использует общие модели и
JSON-хранилище. В проекте настроены SQLite и стандартная Django admin;
предметные данные пока хранятся в JSON, отдельные Django ORM-модели,
аутентификация владельцев и формы редактирования ещё не реализованы.

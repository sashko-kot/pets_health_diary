# Дневник здоровья грызунов

Учебное приложение для учёта домашних грызунов и наблюдений за их здоровьем.
Консольная версия проекта дополнена веб-интерфейсом на Django.

## 1. Назначение проекта

Проект помогает вести сведения о питомцах и их хозяевах, следить за весом,
активностью, аппетитом и симптомами, а также просматривать историю записей
осмотров. Питомец связан с хозяином по `owner_id`, запись дневника — с
питомцем по `pet_id`.

Разработка ведётся поэтапно: консольная версия ПР3 сохранена, а веб-интерфейс
расширяется возможностями Django.

## 2. Используемые технологии

- Python 3.13;
- Django 5.2;
- Django Template Language (DTL);
- HTML5 и CSS3;
- JavaScript;
- Bootstrap 5.3;
- JSON для хранения данных предметной области;
- Git;
- pytest и flake8.

## 3. Предметная область и данные

В приложении используются три основные сущности:

- **Хозяин (Owner)** — идентификатор, имя и электронная почта;
- **Питомец (Pet)** — идентификатор, имя, вид, ID хозяина, текущий и
  рекомендованный вес;
- **Запись здоровья (HealthRecord)** — идентификатор, ID питомца, дата
  осмотра, активность, аппетит, симптомы и вес.

Собственные Python-классы и операции предметной области находятся в каталоге
`models/`. Исходные данные хранятся в JSON-файлах:

- `data/owners.json` — хозяева;
- `data/pets.json` — грызуны и ссылки на хозяев;
- `data/records.json` — записи осмотров и ссылки на питомцев.

Загрузка и сохранение данных выполняются модулем `storage.py`. Django ORM
для предметных данных пока не используется; формы и работа с базой данных
предусмотрены на следующих этапах проекта.

## 5. Веб-интерфейс

Веб-часть использует представления Django, которые загружают данные,
подготавливают контекст и вызывают шаблоны через `render()`. HTML не
формируется строками в Python-коде; вспомогательная функция `page()` после
перехода на шаблоны не используется.

Основные страницы:

- главная страница с описанием проекта и переходами к разделам;
- список питомцев с видом, весом и хозяином каждого грызуна;
- карточка питомца с данными хозяина и историей здоровья;
- список записей дневника;
- карточка отдельной записи со сведениями о питомце и хозяине.

Для отсутствующего питомца, записи или URL возвращается HTTP 404 с
соответствующим сообщением.

## 6. Django Template Language

### Базовый шаблон и наследование

Общая структура сайта определена в `templates/base.html`. Базовый шаблон
задаёт HTML-документ, заголовок страницы, Bootstrap, собственный CSS,
навигацию, основной контейнер, подвал и подключение JavaScript.

Дочерние шаблоны наследуют общий каркас:

```django
{% extends "base.html" %}

{% block title %}Заголовок страницы{% endblock %}

{% block content %}
    ...
{% endblock %}
```

### Включаемые шаблоны

Повторяющиеся элементы вынесены в отдельные шаблоны:

- `templates/includes/navigation.html` — навигация сайта;
- `pets/templates/pets/includes/pet_card.html` — карточка питомца в списке;
- `records/templates/records/includes/symptom_status.html` — статус симптомов.

Они подключаются директивой `{% include %}`.

### Контекст, циклы и условия

Представления передают данные в шаблоны через словарь контекста. Например,
список питомцев передаётся по ключу `pets`, а записи здоровья — по ключу
`records`. В шаблонах используются `{% for %}` для вывода коллекций,
`{% empty %}` для пустых списков и `{% if %}` для условного отображения
содержимого.

## 7. Фильтры шаблонов

В шаблонах используются стандартные фильтры DTL для представления данных:

- `{{ pets|length }}` и `{{ records|length }}` — количество элементов;
- `{{ pet.name|default:"Без имени" }}` — значение по умолчанию;
- `{{ record.recorded_on|date:"d.m.Y" }}` — форматирование даты.

Фильтры отвечают за отображение и не заменяют бизнес-логику Python-кода.

## 8. URL-маршрутизация

Корневой файл `config/urls.py` подключает маршруты трёх приложений. В каждом
`urls.py` задано пространство имён через `app_name`; в шаблонах ссылки
формируются тегом `{% url %}`, а не жёстко заданными адресами.

| Страница | URL | Именованный маршрут |
| --- | --- | --- |
| Главная | `/` | `homepage:index` |
| Список питомцев | `/pets/` | `pets:pets_list` |
| Карточка питомца | `/pets/<int:pet_id>/` | `pets:pet_detail` |
| Список записей | `/records/` | `records:records_list` |
| Детали записи | `/records/<int:record_id>/` | `records:record_detail` |
| Администрирование | `/admin/` | Django admin |

Например, ссылка на карточку питомца формируется так:

```django
{% url "pets:pet_detail" pet.id %}
```

## 9. Статические файлы

CSS, изображение и JavaScript находятся в `homepage/static/homepage/`.
В шаблонах загружается библиотека static и используются пути Django:

```django
{% load static %}
{% static "homepage/css/style.css" %}
{% static "homepage/img/logo.svg" %}
{% static "homepage/js/main.js" %}
```

Собственный `style.css` оформляет навигацию, карточки, панели и подвал;
Bootstrap сохраняется для сетки, кнопок и других компонентов. Скрипт
`main.js` переключает светлую и тёмную тему интерфейса.

## 10. Хранение и загрузка данных

Данные предметной области остаются в JSON:

```text
data/owners.json
data/pets.json
data/records.json
```

`storage.py` преобразует JSON в объекты классов из `models/`; эти же сущности
используются консольной и веб-версиями проекта. Файл SQLite может
использоваться самим Django для служебных приложений, но данные хозяев,
питомцев и записей пока не переведены на Django ORM.

## 11. Основные модули и представления

- `models/owners.py`, `models/pets.py`, `models/records.py` — классы
  предметной области и операции с ними;
- `storage.py` — загрузка и сохранение JSON;
- `main.py` — консольный интерфейс;
- `homepage/views.py` — главная страница и обработчик ошибки 404;
- `pets/views.py` — список питомцев и карточка выбранного питомца;
- `records/views.py` — список записей и карточка отдельного осмотра;
- `config/settings.py` — настройки Django и список приложений;
- `config/urls.py` — подключение маршрутов приложений.

## 12. Тестирование

Тесты находятся в `homepage/tests.py`. Они проверяют операции предметной
области, загрузку и сохранение данных, отображение страниц и обработку
несуществующих идентификаторов.

Запуск тестов:

```powershell
.\venv\Scripts\python.exe -m pytest -v
```

## 13. Проверка качества кода

Для проверки проекта и стиля Python-кода используются Django system check
и flake8:

```powershell
.\venv\Scripts\python.exe manage.py check
.\venv\Scripts\python.exe -m flake8 . --extend-exclude=venv
```

## 14. Установка и запуск

Из корневого каталога проекта в PowerShell установите зависимости и запустите
сервер разработки:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py runserver
```

Веб-интерфейс будет доступен по адресу `http://127.0.0.1:8000/`. Для запуска
консольной версии выполните:

```powershell
.\venv\Scripts\python.exe main.py
```

## 15. Работа с Git

В проекте реализованы:

- консольная версия и предметные классы хозяев, питомцев и записей здоровья;

- передача данных через контекст, циклы, условия и фильтры DTL;
